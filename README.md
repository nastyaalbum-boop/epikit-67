# Извлечение 50 признаков из кардиологических выписных эпикризов

Решение кейса Yandex Cloud: пакетная обработка выписных эпикризов пациентов с ОКС
и преобразование свободного текста в JSON по шаблону организаторов.

Все данные синтетические. Решение предназначено для исследовательского и демонстрационного
использования и не должно применяться для постановки диагноза или принятия клинических решений.

## Запуск

Нужен только Python 3.9+, внешних библиотек нет — в обоих режимах.

    python run.py --input documents --output result

Для каждого входного файла `имя.md` создаётся `result/имя.json`: девять групп, 50 ключей,
все значения — строки. Если значение не найдено, пишется «не указано».

Дополнительно создаются:

- `evidence/имя.json` — те же поля с цитатой из текста, подтверждающей значение;
- `review_report.csv` — список анкет, которые стоит проверить вручную, с причиной.

## Веб-интерфейс

    python app.py

Откроется страница http://127.0.0.1:8000 (сервер доступен только с этого компьютера, библиотек не требует).

- **Пакет.** Загрузка любого количества эпикризов: перетаскиванием файлов или папки, архивом `.zip`
  или указанием пути к папке на диске. Прогресс, сводка, таблица документов, кнопка «Скачать result.zip»
  (внутри `result/`, `evidence/` и `review_report.csv`).
- **Документ.** Текст эпикриза с подсветкой фрагментов и анкета; наведение на поле показывает его цитату.
- **Качество.** Сверка с ручной разметкой и заполненность полей в текущем пакете.
- Переключатель «Локальный режим / Локальный режим + YandexGPT» — те же два режима, что и в командной строке.

## Два режима

| Режим | Команда | Что делает |
|---|---|---|
| Только правила | `python run.py --input documents --output result` | работает без сети, результат одинаков при каждом запуске |
| Правила + YandexGPT | `python run.py --input documents --output result_llm --evidence evidence_llm --llm` | поля, которые правила оставили пустыми, дозаполняет модель |

Во втором режиме модель вызывается только для документов, где правило не нашло значение, хотя в тексте
есть намёк на него. Ответ принимается, если модель привела цитату, которая дословно есть в эпикризе,
и значение проходит проверку формата; иначе остаётся «не указано». При сбое сети сохраняется результат правил.

Настройка второго режима: скопировать `.env.example` в `.env` и вписать API-ключ сервисного аккаунта
и идентификатор каталога Yandex Cloud. Проверка связи: `python llm.py`.
Пример документа, на котором режимы дают разный результат: `examples/llm-demo.md`.

## Подход

Гибридный конвейер на правилах, без обучаемых моделей:

1. Чтение файла с автоопределением кодировки (UTF-8, UTF-16, Windows-1251).
2. Правила на каждое поле: регулярные выражения и словари синонимов, сокращений и препаратов.
3. Учёт контекста: отрицания («отрицает», «не выявлено»), повторные измерения
   («при повторном осмотре», «контроль перед выпиской»), рекомендации («курение исключить»).
4. Нормализация: даты в ДД.ММ.ГГГГ, десятичная точка, без единиц измерения, давление как 140/90.
5. Самопроверка: согласованность дат, диапазоны значений, соответствие диагноза, ЭКГ и кода МКБ.
6. Запасной проход: если в ключевом слове опечатка в одну букву («креатнин», «Kilip»),
   слово исправляется и документ разбирается повторно; в цитате ставится пометка об исправлении.

Почему правила, а не языковая модель: тексты однотипные, а правила дают одинаковый результат
при каждом запуске, не придумывают значений, работают без сети и обрабатывают 100 документов
примерно за 2 секунды. Каждое значение сопровождается дословной цитатой из исходного текста.

## Формат значений

Формат взят из колонки «Пример: текст → JSON» в описании кейса; все 50 примеров организаторов
проходят (`test_official_examples.py`).

| Поле | Значения |
|---|---|
| `type_acs` | STEMI / NSTEMI / NA |
| `mi_localisation` | A / I / L / N; если стенка в тексте не названа — по коду МКБ-10 (I21.0 → A, I21.1 → I, I21.2 → L) |
| `art_hyper`, `atr_fibril`, `copd`, `dm`, `tlt`, `ecg_avb`, `ecg_elevation` | 1 / 0 |
| `killip` | 1–4 |
| `ckd`, `hf` | «ХБП 3А», «ХСН 2А, ФК 2» |
| `smoking` | три статуса: «Курит», «Не курит», «Бросил курить» |
| `ecg_rythm` | «синусовый», «фибрилляция предсердий» |
| `card_trop` | положительный / отрицательный |
| `echo_mr`, `echo_zone`, `rg_pc` | фрагмент текста: «Митральная регургитация 2 ст.» |
| `ca_fact` | Y / R / N |
| `ca_lad`, `rca` | 0 / 1 / 2 |
| лекарства | строка назначения: «Тикагрелор 90 мг 2 раза в день» |
| числа | как в тексте, с десятичной точкой: «7.0», «141» |

## Проверка качества

    python evaluate.py                 # сверка с ручной разметкой gold/ (27 документов)
    python test_official_examples.py   # 50 примеров из описания кейса
    python test_synonyms.py            # 82 альтернативные формулировки
    python test_robustness.py          # пустые файлы, другая кодировка, текст без переводов строк
    python test_typos.py               # опечатки в ключевых словах
    python test_llm.py                 # режим --llm на заглушке, без сети

На ручной разметке при точном сравнении строк совпадает 1350 из 1350 значений.
Разметка приведена к формату примеров организаторов.

## Ограничения

- Правила настроены на 100 открытых документов; формулировки, которых нет ни в них,
  ни в словарях синонимов, дадут «не указано».
- Формат значений соответствует примерам из описания кейса и ответам наставника:
  аспирин всегда «АСК», при отсутствии застоя на рентгене записывается сама фраза заключения.
- Для бинарных полей 0 означает отсутствие упоминания или явное отрицание, а не заключение об отсутствии болезни.
- Самопроверка находит противоречия внутри анкеты, но не ошибки, которые выглядят правдоподобно.

## Состав

| Файл | Назначение |
|---|---|
| `run.py` | пакетный запуск из командной строки |
| `app.py`, `web/index.html` | веб-интерфейс |
| `extract.py` | правила извлечения |
| `validate.py` | самопроверка анкеты |
| `llm.py` | запасной путь через YandexGPT (флаг `--llm`) |
| `typo.py`, `vocab.txt` | исправление опечаток в ключевых словах и словарь обычных слов |
| `evaluate.py` | сверка с эталоном |
| `template.json` | шаблон ответа организаторов |
| `documents/` | 100 открытых эпикризов |
| `result/` | результат для открытых эпикризов |
| `gold/` | ручная разметка |
